# Internationalization

Wrap every user-facing string from the start. Retrofitting i18n means touching every file again.

## Text domain rules

The text domain identifies which translation set a string belongs to.

- **Must match the plugin slug exactly** — folder `my-plugin` → domain `my-plugin`. On WordPress.org it must be the slug in `wordpress.org/plugins/<slug>`.
- **Lowercase, dashes not underscores, no spaces.**
- **Must be a literal string** — never a variable or constant. The extractor parses source statically and cannot resolve them.

```php
__( 'Save changes', 'my-plugin' );      // correct
__( 'Save changes', $domain );          // WRONG — no strings extracted
__( 'Save changes', MY_TEXTDOMAIN );    // WRONG — same reason
```

Every translation call needs the domain. Omitting it sends the string to core's `default` domain.

## Headers

```php
/**
 * Text Domain: my-plugin
 * Domain Path: /languages
 */
```

`Domain Path` must start with a slash. Both are optional for plugins in the official directory (WP 4.6+), since the domain must equal the slug anyway.

## Function reference

**Basic**

| Function | Signature | Use |
|----------|-----------|-----|
| `__()` | `__( $text, $domain )` | Return translated |
| `_e()` | `_e( $text, $domain )` | Echo translated |
| `_x()` | `_x( $text, $context, $domain )` | Return, with context |
| `_ex()` | `_ex( $text, $context, $domain )` | Echo, with context |
| `_n()` | `_n( $single, $plural, $number, $domain )` | Plural form |
| `_nx()` | `_nx( $single, $plural, $number, $context, $domain )` | Plural + context |

**Translate and escape — prefer these for anything printed**

| Function | Context |
|----------|---------|
| `esc_html__()` / `esc_html_e()` | HTML body |
| `esc_attr__()` / `esc_attr_e()` | HTML attribute |
| `esc_html_x()` / `esc_attr_x()` | With context |

Translations are third-party content — treat them as untrusted and escape them. `_e()` and `__()` output raw.

**Deferred plurals** — when the string is defined before the count is known:

```php
$noop = _n_noop( '%s comment', '%s comments', 'my-plugin' );
// later:
printf( translate_nooped_plural( $noop, $count, 'my-plugin' ), number_format_i18n( $count ) );
```

`_n_noop()` does not translate; it registers the strings for extraction.

**Locale-aware formatting** — `number_format_i18n( $number )`, `date_i18n( $format, $timestamp )`.

## Placeholders

Never interpolate a variable into a translatable string:

```php
// WRONG — extracted string never matches the runtime string
_e( "Your city is $city.", 'my-plugin' );

// CORRECT
printf(
    /* translators: %s: city name */
    esc_html__( 'Your city is %s.', 'my-plugin' ),
    esc_html( $city )
);
```

**With two or more placeholders, always number them.** Word order differs between languages, and numbered placeholders let translators reorder without touching code:

```php
printf(
    /* translators: 1: city name, 2: ZIP code */
    esc_html__( 'Your city is %1$s, and your ZIP is %2$s.', 'my-plugin' ),
    esc_html( $city ),
    esc_html( $zip )
);
```

**Use single quotes** around these strings — in double quotes PHP reads `$s` as a variable.

## Plurals

```php
printf(
    esc_html( _n( '%s comment', '%s comments', $count, 'my-plugin' ) ),
    number_format_i18n( $count )
);
```

Use `'%s item'` rather than `'One item'` for the singular — some languages use the singular form for 21, 31, and so on. Many languages have more than two plural forms; never hand-roll an `if ( $n === 1 )` in place of `_n()`. The count is normally used twice: once to select the form, once to render the number.

## Context

Same English word, different meanings:

```php
_x( 'Post', 'noun', 'my-plugin' );   // "Edit this post"
_x( 'Post', 'verb', 'my-plugin' );   // "Post your comment"
```

## Translator comments

Must start with `translators:` and be the last comment immediately before the call. Use block comments.

```php
/* translators: %1$s: plugin name, %2$s: version number */
printf( esc_html__( '%1$s version %2$s is active.', 'my-plugin' ), $name, $version );
```

Required whenever a placeholder's meaning is not self-evident. Plugin Check flags missing ones.

## Loading translations

```php
add_action( 'init', function () {
    load_plugin_textdomain( 'my-plugin', false, dirname( plugin_basename( __FILE__ ) ) . '/languages' );
} );
```

**Usually unnecessary.** Since WP 4.6, translations from translate.wordpress.org load automatically. A plugin hosted on WordPress.org does not need `load_plugin_textdomain()` at all, as long as `Requires at least` is 4.6+. Keep it only when distributing outside the directory or shipping your own `.mo` files.

**Never call a translation function before `init`.** Doing so triggers the `_load_textdomain_just_in_time` notice in WP 6.7+ and produces untranslated output. That means no translating at file-include time, in a constructor that runs on include, or in a class property default.

## JavaScript

```php
wp_enqueue_script( 'myplugin-app', MYPLUGIN_URL . 'build/index.js',
    array( 'wp-i18n', 'wp-element' ), MYPLUGIN_VERSION, true );

wp_set_script_translations( 'myplugin-app', 'my-plugin', MYPLUGIN_DIR . 'languages' );
```

The script must declare `wp-i18n` as a dependency.

```js
import { __, _x, _n, sprintf } from '@wordpress/i18n';

__( 'Hello', 'my-plugin' );
sprintf( __( 'Your city is %s.', 'my-plugin' ), city );
```

JS needs **JSON** translation files, not `.po`/`.mo`. Generate them:

```bash
wp i18n make-pot . languages/my-plugin.pot --domain=my-plugin
wp i18n make-json languages/my-plugin-fr_FR.po --no-purge
wp i18n make-mo languages/
```

## Writing translatable strings

- Whole sentences, not fragments — word order varies by language.
- Never concatenate translated pieces; use one string with placeholders.
- Assume translations can be **twice as long**; design UI accordingly.
- Keep HTML out of strings where possible; if unavoidable, use placeholders for the tags.
- No leading or trailing whitespace.
- Reuse identical strings rather than creating near-duplicates (`'Posts:'` vs `'Posts'`).
- Never translate an empty string — it is reserved by gettext.
- Don't translate URLs unless a localized version genuinely exists.

## Common mistakes

| Mistake | Consequence |
|---------|-------------|
| Variable or constant as text domain | No strings extracted |
| Domain ≠ plugin slug | Language packs never load |
| Interpolated variable in the string | Extracted string never matches runtime |
| Concatenating translated fragments | Untranslatable; word order locked to English |
| Missing domain argument | String goes to core's domain |
| Unnumbered `%s` with 2+ args | Translator cannot reorder |
| Double quotes around `%1$s` | PHP expands `$s` as a variable |
| `_e()` / `__()` for HTML output | Unescaped — use `esc_html_e()` |
| Translation call before `init` | Doing-it-wrong notice, untranslated output |

## Tooling

`wp i18n make-pot ./` generates the POT file. PHPCS's `WordPress.WP.I18n` sniff catches variable domains, missing domains, and missing translator comments:

```xml
<rule ref="WordPress.WP.I18n">
    <properties>
        <property name="text_domain" type="array" value="my-plugin"/>
    </properties>
</rule>
```
